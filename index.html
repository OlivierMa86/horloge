Guide : Liaison Jeedom (192.168.1.23) & Jeedom Connect

  1. 1. Comment fonctionne la mise en veille par l'Alarme Jeedom ? L'horloge interroge votre commande d'état d'alarme Jeedom (`http://192.168.1.23/core/api/jeeApi.php?apikey=...&type=cmd&id=...`).
    • Alarme activée (1) : L'horloge s'éteint (écran 100 % noir `#000000`) et stoppe ses calculs.
    • Alarme désactivée (0) : L'horloge se rallume automatiquement dès qu'elle détecte `0` !
  2. 2. Important : HTTP local (`192.168.1.23`) vs HTTPS GitHub Pages Par sécurité, Safari sur iPad bloque les requêtes vers une IP locale `http://192.168.1.23` si la page est ouverte depuis `https://olivierma86.github.io`. Vous avez **3 solutions simples** :
    • Option A (Dans Jeedom Connect) : Ajoutez une WebView dans Jeedom Connect ou ouvrez l'horloge via votre URL HTTPS Jeedom (DNS Jeedom `https://xxx.dns.jeedom.com`).
    • Option B (Héberger l'horloge directement sur votre Jeedom `192.168.1.23`) : Copiez ce dossier `horloge` dans `/var/www/html/horloge` sur votre Jeedom (en 1 commande SSH : `cd /var/www/html && git clone https://github.com/OlivierMa86/horloge.git`). Puis sur l'iPad, ouvrez **`http://192.168.1.23/horloge/`** ! Plus aucun blocage HTTPS/CORS, même si Internet est coupé !
    • Option C (Piloter par URL depuis un scénario Jeedom) : Vous pouvez aussi forcer la mise en veille ou le réveil par paramètre d'URL : `?standby=1` (veille) ou `?standby=0` (réveil).
